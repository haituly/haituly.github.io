Pipeline architecture

run_pipeline.py orchestrates all five stages
01 · Extract

SuiteQL against NetSuite

Wrote SuiteQL queries directly against NetSuite's database, joining multiple tables to reach fields not exposed in standard reports.

02 · Paginate

Bypass the 10K row cap

NetSuite's API caps result sets at 10,000 records. Built a Python pagination layer to page through the full extract without data loss.

03 · Load

Authenticate and load to BigQuery

Python handles Google Cloud authentication and loads raw extracts into BigQuery across the fact and dimension tables.

04 · Transform

Medallion architecture in SQL

Bronze → silver → gold layers in BigQuery SQL clean, conform, and model the data into the star schema used by Power BI.

05 · Schedule

Orchestrate and run unattended

run_pipeline.py chains extract, load, and transform into one script, scheduled with Windows Task Scheduler for hands-off, recurring runs.

Challenges solved

  • NetSuite's 10,000-record API limit: single queries silently truncated at 10K rows. Solved with a pagination method that iterates through offsets until the full dataset is captured, with no record loss.
  • Reverse-engineering an undocumented schema: NetSuite's underlying table structure isn't built for easy querying. Getting to the right fields took extensive testing and joins across multiple tables to trace how records actually relate to each other.
  • Query performance and correctness: iterated on SuiteQL joins repeatedly to get accurate, complete pulls before the data was reliable enough to load into BigQuery.
